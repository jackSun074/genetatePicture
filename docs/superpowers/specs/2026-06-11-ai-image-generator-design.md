# AI 生图网页工具设计规格

## 背景

当前工作区为空目录，尚未存在项目代码、文档或 Git 仓库。本规格定义一个纯前端 AI 生图网页工具，用于连接用户自己的自定义中转站接口。用户填写完整请求地址、API Key、模型和生图参数后，可以生成图片、查看结果、复制链接、下载图片并保留本地历史记录。

## 目标

- 创建一个可静态部署的纯前端单页应用。
- 用户可以自行填写完整请求地址、API Key 和模型名。
- 用户可以填写提示词，并通过画面比例、风格、尺寸、质量、生成数量等参数辅助生成图片。
- 应用直接从浏览器请求用户填写的完整请求地址，不自动拼接任何路径。
- 配置和历史记录保存在当前浏览器的 `localStorage`。
- 支持展示图片、下载图片、复制图片链接和查看历史记录。

## 非目标

- 不实现后端服务。
- 不实现后端代理。
- 不实现数据库。
- 不实现登录、多用户或跨设备同步。
- 不实现复杂图库、收藏、分组或批量管理。
- 不隐藏 API Key；Key 仅保存在用户当前浏览器本地。

## 技术方案

项目采用 `Vite + React + TypeScript` 构建纯前端单页应用。应用直接调用用户填写的自定义中转站完整请求地址，并按兼容 OpenAI Images API 的请求体发送参数。

首版不引入后端，因此部署目标是静态站点。可部署到 GitHub Pages、Vercel、Netlify 或任意静态文件服务器。

## 模块划分

### 配置模块

职责：管理接口相关配置。

字段：

- `requestUrl`：完整请求地址，由用户填写。
- `apiKey`：API Key，由用户填写。
- `model`：模型名，由用户填写，例如 `gptimage-2`。

行为：

- 保存配置到 `localStorage`。
- 页面初始化时从 `localStorage` 恢复配置。
- API Key 输入框支持显示和隐藏。
- 页面需要明确提示：API Key 仅保存在本机浏览器 `localStorage`。

### 生图表单模块

职责：管理用户输入的生图参数。

字段：

- 主提示词 `prompt`
- 负面提示词 `negativePrompt`
- 画面比例 `aspectRatio`
- 风格 `style`
- 尺寸 `size`
- 质量 `quality`
- 生成数量 `count`

首版支持常用参数，不加入 seed、参考图、强度或批量任务。

### 提示词组装模块

职责：将用户输入和辅助选项合并为最终提示词。

规则：

- 用户主提示词始终放在最前面。
- 风格作为补充描述追加，例如 `Style: cinematic`。
- 比例作为构图约束追加，例如 `Aspect ratio: 16:9`。
- 负面提示词追加为 `Avoid: blurry, low quality, watermark`。
- 不使用复杂 prompt 模板，避免首版过度设计。

### API 客户端模块

职责：发起生图请求并解析响应。

请求规则：

- 请求地址直接使用用户填写的 `requestUrl`。
- 前端不自动拼接 `/v1/images/generations` 或其他路径。
- 请求头使用 `Authorization: Bearer <apiKey>`。
- 请求体包含用户填写的 `model` 和组装后的 `prompt`。
- `size`、`quality`、`n` 按兼容 OpenAI Images API 的字段发送。

响应解析：

- 优先支持 `data[].url`。
- 同时兼容 `data[].b64_json`。
- 如果两种字段都不存在，视为响应格式不符合预期。

### 结果展示模块

职责：展示生成结果并提供基础操作。

能力：

- 图片网格展示。
- 每张图片支持下载。
- 每张图片支持复制图片链接。
- 对于 base64 图片，下载可直接处理。
- 对于远程 URL 图片，如果下载受跨域限制，提供打开原图或复制链接作为兜底。

### 历史记录模块

职责：保存最近生成记录。

保存内容：

- 图片 URL 或 base64 数据。
- 主提示词和最终提示词。
- 模型。
- 画面比例、风格、尺寸、质量、数量。
- 生成时间。

约束：

- 历史记录保存到 `localStorage`。
- 最多保留最近 50 条。
- 用户可以清空历史记录。

## 页面与交互设计

页面采用单页工作台布局。

桌面端：

- 顶部显示应用标题、接口连接状态、清空配置和清空历史入口。
- 左侧为配置区，包含请求地址、API Key、模型和保存按钮。
- 中间为生图表单区，包含提示词和参数。
- 右侧为结果区，展示生成状态、错误提示和图片结果。
- 历史记录位于底部或右侧折叠区。

移动端：

- 配置区、表单区、结果区、历史记录按纵向排列。
- 操作按钮保持易点击，输入区避免过宽布局。

核心交互：

- 用户填写并保存 `requestUrl`、`apiKey`、`model`。
- 用户填写提示词并选择参数。
- 点击“生成图片”后进入 loading 状态，并禁用重复提交。
- 成功后展示图片并写入历史记录。
- 失败后展示可读错误，不清空用户已填写内容。

## 数据流

1. 页面加载时从 `localStorage` 读取配置和历史记录。
2. 用户修改配置后可以保存到 `localStorage`。
3. 用户点击生成图片。
4. 前端校验 `requestUrl`、`apiKey`、`model` 和 `prompt`。
5. 提示词组装模块生成最终 prompt。
6. API 客户端向用户填写的完整 `requestUrl` 发送请求。
7. API 客户端解析 `data[].url` 或 `data[].b64_json`。
8. 结果展示模块渲染图片。
9. 历史记录模块将结果和关键参数写入 `localStorage`。

## 错误处理

应用需要处理以下错误：

- 配置缺失：`requestUrl`、`apiKey`、`model` 或 `prompt` 为空时，不发送请求并提示对应字段。
- URL 格式错误：提示“请输入完整请求地址，例如 https://api.example.com/images”。
- 网络失败：提示“请求失败，请检查请求地址、网络或 CORS 设置”。
- 鉴权失败：如果返回 `401` 或 `403`，提示“API Key 无效或无权限”。
- 接口返回错误：优先展示接口返回的 `error.message`，没有则展示 HTTP 状态码。
- 响应格式不支持：如果没有 `data[].url` 或 `data[].b64_json`，提示“接口响应格式不符合预期”。
- 重复提交：生成中禁用按钮，避免重复请求。

## 安全与限制

- 这是纯前端应用，无法隐藏 API Key。
- API Key 会保存在用户当前浏览器的 `localStorage`，不上传到其他服务。
- 如果自定义中转站没有开放 CORS，浏览器会阻止请求。
- 首版不提供后端代理来绕过 CORS 或隐藏 Key。
- 历史记录保存在本地浏览器，清理浏览器数据会导致历史丢失。

## 验收标准

功能验收：

- 用户可以填写并保存 `requestUrl`、`apiKey`、`model`。
- 刷新页面后配置可以从 `localStorage` 自动恢复。
- 用户可以填写主提示词、负面提示词、比例、风格、尺寸、质量和数量。
- 点击生成后会向用户填写的完整 `requestUrl` 发送请求，不自动拼接路径。
- 请求体包含用户填写的 `model` 和组装后的 `prompt`。
- 成功响应 `data[].url` 时能展示图片。
- 成功响应 `data[].b64_json` 时也能展示图片。
- 每张图片可以下载。
- 每张图片可以复制链接。
- 图片结果会写入本地历史记录。
- 历史记录最多保留最近 50 条。
- 用户可以清空历史记录。

错误验收：

- 必填项为空时不会发请求，并显示明确提示。
- 接口返回 `401` 或 `403` 时显示鉴权错误。
- 网络失败或 CORS 失败时显示请求失败提示。
- 响应格式不符合预期时显示格式错误提示。
- 生成中按钮禁用，避免重复提交。

技术验收：

- 项目使用 `Vite + React + TypeScript`。
- 不引入后端服务。
- 不使用数据库。
- 不实现登录系统。
- 可通过静态部署运行。
- API 调用、`localStorage` 存储、提示词组装拆成独立模块，避免所有逻辑堆在一个组件里。

## 后续扩展方向

以下能力不属于首版范围，但后续可以独立设计：

- 后端代理，用于隐藏 API Key 和规避 CORS。
- 参考图上传与图生图。
- 历史记录收藏、分组和搜索。
- 多接口预设。
- Prompt 模板管理。
- 批量生成任务。
